# Месяц премии за задачу

Реализовано и выложено на SberCloud 2026-11-10. Одна личная задача содержит одну премию за один месяц.

## Поведение

- При назначении положительной премии руководитель выбирает месяц и год. Значение по умолчанию —
  «По дате подтверждения».
- В карточке командной задачи есть «Изменить месяц премии». Работает до и после приёмки.
- Премия включается в начисления только при `status='done'` и непустом `approved_at`.
- Перенос не меняет сумму, сотрудника, статус или время приёмки, не начисляет очки и не отправляет Telegram.
- Возврат выбора к «По дате подтверждения» очищает `reward_month`.
- График, расшифровка начислений, личные выплаты и долг в «Деньгах» используют один месяц:
  `COALESCE(reward_month::timestamptz, approved_at)`. Исторические NULL сохраняют прежние периоды.
- Фактические выплаты и обязательства не меняются. Для сентября и октября создаются две задачи.

## API и миграция

`POST /api/tasks` принимает необязательный `rewardMonth: "YYYY-MM" | null`.
`PATCH /api/tasks/:id/reward-month` принимает обязательный `rewardMonth: "YYYY-MM" | null`.
Изменение доступно только owner/manager для личной задачи с положительной премией, кроме снятых задач.
Изменение фиксируется в `audit_log` как `task_reward_month_update`.

Миграция `053_task_reward_month.sql` добавляет nullable date с ограничением на первое число месяца.
Существующие строки не обновляются. Миграция должна примениться **до запуска нового кода**.
Обычный Docker entrypoint уже выполняет миграции перед стартом API. Фронт требует пересборки образа.
При откате кода колонку можно оставить: она обратно совместима, но старый код не учитывает выбранные месяцы.

## Проверки

```sh
npm run check
npm run build
node --check apps/web/app.js
node --import tsx --test tests/task-reward-month.test.mjs
```

PostgreSQL-проверка использует только временные таблицы и `search_path=pg_temp`, затем ROLLBACK:

```sh
TEST_DATABASE_URL=<тестовая-БД> node tests/task-reward-month-postgres.mjs
```

Проверяются повторное применение миграции, прежний месяц при NULL, перенос ноябрь → сентябрь → октябрь,
возврат к месяцу подтверждения, две премии по 5000 за два месяца, исключение непринятых/снятых задач,
совпадение всех четырёх расчётов и сохранение фактической даты приёмки.

Форма проверена локально на широком и узком экранах. Два обычных select обеспечивают выбор месяца
в Safari без зависимости от поддержки `input[type=month]`.

- Первый запуск остановился из-за AppleDouble `._053_task_reward_month.sql` из macOS-архива.
  Выполнен откат к прежнему образу, служебные файлы удалены, сборка проверена и выпуск повторён успешно.
  Загрузчик миграций теперь игнорирует скрытые файлы. Для передачи использовать архивы без AppleDouble
  (например Python tarfile), проверять отсутствие `._*` и нулевых байтов в SQL внутри образа до перезапуска.
