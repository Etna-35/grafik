# «Деньги» — владельческий экран (замена «Кассы»)

Статус: на проде за флагом `money_page` (по умолчанию ВЫКЛЮЧЕН), 2026-07-27.
Заменяет раздел «Касса» (`treasury.ts`, `docs/treasury-planner.md`) — тот код и таблицы НЕ удалены.

## Почему «Касса» не пошла (диагноз по данным прода)

- Прожила 3 дня: 17–20 июня 2026. Последний снимок остатка — 20.06 (50 000 ₽), с тех пор якорь прогноза протух.
- 2 платежа остались в статусе `planned` со сроками 24–25 июня → вечная красная просрочка.
- Конверты копили 30%/5% от каждой закрытой смены с 01.06 и без списаний: к концу июля показывали
  «можно потратить на закуп ~614 000 ₽» — цифра, которой никто не верит.
- `finance_expenses` («внести расход» в Финансах) — 0 записей за всё время существования.

Общий вывод: **всё, что требует ежедневного ручного ввода от владельца, в этом проекте умирает.**
Живёт то, что приезжает само (закрытия смен, ФОТ из графика, отчёты в Telegram). Касса требовала
ежедневно вводить остаток счёта, каждую трату и каждый платёж — и не пережила первую неделю.
Плюс её ядро (cash-flow по расчётному счёту) в принципе не имеет источника данных: интеграции с банком нет.

## Принцип нового раздела

**Ноль ежедневного ручного ввода.** Руками — только две вещи и обе редкие:
1. Закуп за месяц, одной цифрой (раз в месяц, из банк-выписки). Пока не введён — считается по нормативу
   30% от выручки и **явно помечается «оценка»**.
2. Список обязательных платежей (аренда/ЖКХ/налог), с отметкой «повторяется каждый месяц».

Всё остальное берётся из того, что уже есть: `shift_closings` (выручка, наличные, мойка, такси, доп. расходы,
кальянщики), `schedule_shifts.pay_amount` (ФОТ), `payroll_payouts` (что уже выплачено), `finance_fixed`
(постоянные платежи), `predictRevenue` из `finance.ts` (прогноз до конца месяца).

## Экран (3 карточки, owner-only)

1. **Выручка** — факт месяца, наличные, и главное: **темп ₽/день против прошлого месяца** (сумма месяца
   обманчива из-за разного числа рабочих дней, темп — нет). Для текущего месяца — прогноз и «ещё придёт ~X».
2. **Прибыль** — выручка (прогноз для текущего месяца, факт для прошедшего) минус расходы, расписанные строками:
   ФОТ, кальянщики, закуп, постоянные, мойка, такси, доп. расходы смен. Тут же поле ввода закупа.
3. **Обязательные платежи** — ЗП за прошлый месяц (начислено по графику − выплачено, срок 10-е число) плюс
   точки платежей владельца; просроченные подсвечены. Вердикт одной строкой: «придёт ~X, платить Y, останется Z».

Чего сознательно НЕТ (было в Кассе и не прижилось): остаток на счёте как якорь, конверты закуп/хоз,
ежедневный факт-трат, полоса корзин, копилки с процентами покрытия, календарь месяца, сплиты/переносы платежей.

## Данные и API

- Миграция `045_money_month_facts.sql`: `money_month_facts(month PK, purchase_amount, note, updated_by, updated_at)`.
- Платежи переиспользуют таблицу `treasury_payments` (новой не заводили).
- `GET /api/money?year=&month=` · `PUT /api/money/purchase` `{month:'YYYY-MM', amount|null}` ·
  `POST /api/money/payments` · `POST /api/money/payments/:id/pay` (ежемесячный сам создаётся на след. месяц) ·
  `DELETE /api/money/payments/:id`. Все — строго `role = owner`.
- Плитка «Деньги» инжектится в `getServices` при включённом флаге `money_page`; при включённом флаге плитка
  «Касса» скрывается. Флаг читается прямым запросом к `feature_flags` (импорт `features.ts` в `auth.ts` дал бы цикл).
- `computeMoney(year, month)` экспортирован — можно проверить цифры прямо на сервере без сессии:
  `sudo docker compose exec -T api node -e "import('./apps/api/dist/money.js').then(m=>m.computeMoney(2026,7)).then(d=>console.log(d.profit))"`.

## Известные ограничения (честно, чтобы не принять за истину)

- **Двойной счёт зарплаты наличными.** В «доп. расходах смен» встречаются записи вида «оплата труда (имя)».
  Они же входят в ФОТ по графику → такая выплата учитывается дважды и занижает прибыль. Автоматически
  различить нельзя (поле — свободный текст). Правильный ввод: такие выплаты проводить в разделе «Выплаты».
- **Постоянные платежи** берутся из `finance_fixed` (аренда 300 000 + ЖКХ 130 000 + ПО 16 000 + прочее 6 000
  = 452 000 ₽/мес). Заполнены 11.06.2026 и с тех пор не проверялись; статьи `food`/`bar`/`household` из суммы
  исключены, чтобы не задваивать закуп.
- **ФОТ до июня неполный** — график заполнялся не с самого начала (май: 236 тыс против 459 тыс в июне),
  поэтому май показывает завышенную прибыль. Сравнивать месяцы имеет смысл с июня 2026.
- Закуп по умолчанию — норматив 30%, а не факт. Пока владелец не ввёл цифру, прибыль — оценка сверху.
