# Должность в графике и базовая ставка с месяца

Выложено на SberCloud 10.11.2026 по прямому разрешению пользователя «выкладывай».
Миграция 054 применена. Виктории через API сохранён перевод с ноября 2026: бармен, 270 ₽/час.
Исходные условия официанта 200 ₽/час сохранены; существующие смены и выплаты не изменены.

## Использование

График → нужный месяц → открыть замок → имя сотрудника → «Должность и ставка с этого месяца».
Выбрать должность и базовую ставку, сохранить. Для Виктории: ноябрь 2026, бармен, 270 ₽/час.
Условия действуют с первого числа до следующего перевода; их можно исправить повторным сохранением
в том же месяце. История переводов видна в этом же редакторе. Исходные условия помечены «До первого перевода».

Сохранение условий НЕ пересчитывает существующие смены (включая выбранный месяц).
Для уже записанных ноябрьских смен сначала сверить часы, роли и суммы. Если нужен пересчёт —
отдельная существующая кнопка ставки на месяц: только почасовые смены без role_override этого месяца.
Корпоративы и смены с индивидуальной ролью не пересчитываются. Выплаты не затрагиваются.

Приоритет ставки новых/редактируемых смен: явная ставка дня → ставка на конкретный месяц
(для базовой роли) → базовая ставка на дату смены. Приоритет роли: роль смены → базовая роль на дату.
Ставка месяца действует только в этом месяце; перевод — и в следующих месяцах.

Роль учётной записи employees.role и права доступа не меняются переводом. Ролевые задания и доступы
по-прежнему используют роль учётной записи. Для рабочего графика используется отдельная schedule_role.
После первого перевода исходные schedule_role/hourly_rate/pay_model в админке защищены от правок
API с ошибкой use_employment_terms. Имя, PIN, часы по умолчанию, даты и доступы можно менять как раньше.

## Данные и безопасность истории

Миграция 054 добавляет schedule_employment_terms и SQL-функции schedule_role_on, schedule_rate_on,
schedule_is_waiter_on. Она не записывает условия сотрудникам и не меняет существующие данные.
При первом переводе атомарно сохраняется исходная роль и ставка с технической датой 1900-01-01,
затем запись выбранного месяца. Используется отдельный connection и блокировка строки сотрудника;
редактирование через админку использует тот же порядок блокировки.

API PUT /api/schedule/employment-terms доступен только owner/manager:
`{employeeId, effectiveMonth:"2026-11", scheduleRole:"bar", rate:270}`.
Для dish ставка null, оплата фиксированная. Для остальных ролей целая ставка 1–100000.
Полная история со ставками выдаётся в месячном графике только руководителям.
График, новые смены, сброс ставки месяца и расшифровка используют условия на дату/месяц.
Начисления по-прежнему суммируют сохранённые schedule_shifts.pay_amount, выплаты не меняются.

Для наград за наличный план после даты первого перевода учитываются условия на дату и роль смены.
До первого перевода сохранён прежний алгоритм определения официантов — старые серии не меняются
из-за установки перевода. Сохранение перевода само по себе не запускает перерасчёт премий.

## Проверки

`npm run check`, `node --check apps/web/app.js`, `git diff --check`.

Интеграционный тест использует фактический PostgreSQL-движок PGlite в памяти и фактические функции API.
Не читает .env, не обращается к серверу. Зависимость теста устанавливается отдельно от приложения:

```sh
npm install --prefix /tmp/etna-employment-terms-test --no-audit --no-fund --package-lock=false @electric-sql/pglite
PGLITE_MODULE_URL=file:///tmp/etna-employment-terms-test/node_modules/@electric-sql/pglite/dist/index.js node tests/schedule-employment-terms.test.mjs
```

Проверяется повторное применение миграции, отсутствие автоматических правок, исходные условия,
границы октября/ноября/января, повторное сохранение, rollback, ставка месяца/сброс, роль дня,
корпоративы, принадлежность к наличному плану, защита админки, права API, неверный месяц, выплаты.

## Процедура последующих выпусков

По процедуре HANDOFF с разрешением пользователя: бэкап БД и предыдущего образа → передать изменения
без AppleDouble → сборка/перезапуск api (миграция 054 автоматически) → healthcheck и проверки графика.
В выпуск входят apps/api/src/{schedule,scheduleTerms,admin,cashPlan}.ts, apps/web/app.js и миграция 054.
Не заполнять перевод Виктории миграцией: сохранить через редактор после проверки выпуска.
До и после сравнить контрольные суммы schedule_shifts/payroll_payouts/cash_streak_awards/tasks.
Проверить август–октябрь (роли, суммы, выплаты) и ноябрь; затем сохранить перевод Виктории
и повторить сравнение денежных записей — должны полностью совпасть.

Откат приложения: вернуть предыдущий образ. Добавленные таблица и функции совместимы со старым кодом;
